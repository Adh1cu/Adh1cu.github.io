你家光猫的 256MB 内存里，住着 66 个监控线程

发表于2026-11-15|更新于2026-11-21|科技分享
|总字数:3138|阅读时长:12 分钟|浏览量:

66 个常驻监控线程、一套要连续过载 20 次才肯停手的流量嗅探引擎、一行硬编码在固件底层的新疆电信上报密钥——这不是什么骨干网审查服务器的配置，而是此刻正躺在你家弱电箱里的那台普通光猫。

你以为光猫只是个把光纤转成网线的傻瓜塑料盒。有人把两台主流运营商光猫的闪存固件完整提取出来、反编译到底层字节码，看完之后结论很简单：你每个月交着宽带费和电费，其实是在自己家里，全天候供养着一台监控终端。

先从每个人都遇到过的卡顿说起

如果你认真测过家里的网速，或者在晚高峰打过对延迟敏感的游戏，你多半察觉过某种说不出的古怪：明明办的是 300 兆、500 兆宽带，哪怕把光猫改成纯桥接、用性能强悍的独立软路由拨号，测速指针还是像撞上一堵空气墙，死死卡在 290 兆上下。更诡异的是，那台理论上只负责光电转换的光猫，外壳一年四季烫得像个暖手宝，延迟抖动还经常无缘无故飙到 15 毫秒以上。

为了搞清楚这台小盒子到底在忙什么，视频作者在二手市场收购了两台国内最主流的运营商定制光猫，把固件拆解到了代码级别。第一眼就颠覆常识：一台几乎不跑任何路由转发任务的桥接光猫，双核处理器占用率常年维持在 58% 到 72% 的高位。是谁，在悄无声息地吸干你家光猫六成以上的算力？

256MB 的家底，被一个 Java 虚拟机吃掉一半

先看看这台光猫的硬件：一颗廉价的双核嵌入式芯片，配 256MB 物理内存。在这套嵌入式 Linux 里，正常的内核加二层网桥转发只需要不到 40MB 内存，CPU 占用连 1% 都不到。

然而进程表里赫然盘踞着一个名叫 Felix.jar 的庞然大物。运营商在这台巴掌大的缩水硬件里，硬生生塞进了一整套完整的 Java OSGi 虚拟机容器。实测显示，单单这一个 Java 进程，开机就派生出整整 66 个并发线程，常驻吞掉超过 130MB 物理内存——直接霸占了光猫一半以上的运存。

把固件里的应用目录完整打包拖回本地，9 个核心 JAR 组件逐一反编译，伪装就全剥干净了：有负责云端心跳的 Management 组件，负责局域网拓扑上报的 Andlink 组件，以及最核心的一个——com.chinamobile.smartgateway.cmccdpi。DPI，全称 Deep Packet Inspection，深度报文检测。就是这个缩写，把运营商机房里的深度包检测设备，直接部署到了你家客厅。

桥接模式挡不住它：每个包都被复制一份

如果有人替运营商辩解，说这套组件只是为了“智能家居服务”，那反编译出的字节码就是一封无法抵赖的供词。在 cmccdpi 的核心启动类里，它直接调用底层接口，挂钩在 Linux 内核的 br0 网桥上。这意味着：哪怕你已经把光猫改成纯桥接，自以为它只是一根透明的网线，你家里每台手机、每台电脑发出的每一个数据包，在流经网桥时依然会被强行复制一份，送进 Java 虚拟机做深度特征嗅探。

更直白的证据，藏在启动类里硬编码的四行英文日志里，可以逐字读一读程序员写下的真实逻辑：

第一句，hgudpi start——深度报文监控引擎启动。第二句，CPU rate over limitation, remove QoS and HTTP monitor rules——CPU 超标时，先移除服务质量与 HTTP 监控规则。第三句，CPU rate over limitation, remove TCP UDP monitor rules——CPU 继续爆表，再移除 TCP、UDP 全流量监控规则。第四句是整套代码最荒诞的高潮：CPU rate over limitation more than 20 times, disable the service monitor function——只有当 CPU 连续严重过载报警超过整整 20 次之后，才允许暂时停用监控功能。

优先级写得明明白白：监控是最后一件可以放弃的事，你的网速不是。

它不只是看，还会点名、镜像和自保

继续反编译 Management 等组件，里面还有一整套更精密的取证机制：TCP Monitor、插件指令服务，以及一组名为 CMCC SoftProbe 的软探针接口。它的运作方式是这样的：平时，Andlink 探针像个勤勉的户籍警，定期扫描你家局域网的拓扑结构，把连上网的每部手机、电脑、平板的 MAC 地址、设备主机名、上线下线时间打包汇报给运营商云端。

而一旦云端对某个家庭、甚至某台特定终端“产生兴趣”，根本不需要派人上门：通过长连接向光猫下发一条动态插件指令，光猫内部的镜像守护进程和软探针就会精确锁定目标的局域网 IP 或 MAC 地址，把这台设备发起的所有 DNS 解析请求、以及未加密的 HTTP 访问网址，实时镜像抓走，源源不断回传局端。

想自己动手关掉它？固件里埋着一个看门狗脚本，每隔 60 秒巡检一次进程表，一旦发现监控进程消失，60 秒内就把它重新拉起来。

一行“新疆电信”的密钥，为什么躺在全国的固件里

这会不会只是某一家运营商的个别行为？作者又拆了另一家主流运营商的高版本光猫固件，提取出 21 万多个文件。在一台并非部署在新疆的普通家用光猫里，有一段把家庭局域网设备 MAC 信息定期上报局端的配置：上报协议走的是毫无加密的 HTTP 明文，端口 80；而共享认证密钥那一栏，赫然写着一行字符串——Xinjiang_CTC，新疆电信。

为什么一台全国千家万户都在用的普通光猫，底层硬编码的监控上报密钥会是新疆电信？视频给出的答案残酷而直白：在高压管控试验田里打磨成熟的那套网格化终端监控代码，早就作为标准化工业模板，连一行变量名都懒得改，直接复制粘贴进了全国几千万台家庭光猫的出厂固件。

同一台光猫里还常驻着一套轻量容器引擎和一个每 10 分钟向云端打卡一次的守护进程，容器里预装了五个高权限插件：绘制家庭网络拓扑的、感知内网设备互通状态的、远程自动化控制引擎，以及最危险的一个——流量重定向插件。也就是说，光猫不仅能被动看你的流量，还具备在家庭网关最底层直接劫持特定业务的能力。

你够不到的那条暗线：TR-069

云端为什么能如此肆无忌惮地往你家光猫里塞插件、改配置？答案是光猫内部那条绝大多数用户看不见的暗线：TR-069 远程管理专网。入户光纤里其实并排跑着两条隔离的虚拟管道：一条是业务通道，承载你刷视频、打游戏的流量；另一条是 46 号管理 VLAN，拥有极高的系统特权，而且完全绕过你家路由器的防火墙。

许多人发现，自己好不容易拿到的光猫超级管理员密码，每隔 10 到 30 分钟就莫名失效——这不是错觉。固件逆向显示，运营商布置了双层枷锁：一方面，本地固件内置随机密码程序，你一退出后台或会话超时，它就用硬编码的 AES 密钥自动刷新超级密码，防住普通用户改设置；另一方面，云端管理平台通过 46 号专网时刻巡检，一旦发现你把光猫改成了桥接模式，或者怀疑你在跑大流量上传，就会顺着这条暗道下发指令，半夜悄无声息地把你的配置重置，甚至强行推下限速策略。

怎么把网速和边界一起拿回来

面对这样一台塞满探针的黑盒网关，普通技术爱好者也不是毫无办法。视频在实验环境里做了一次彻底的净化实测：

第一步，斩断监控虚拟机的算力寄生。通过底层维护接口，把拉起 66 线程 Java 虚拟机的启动脚本替换成一个零开销的休眠空壳进程，稳稳骗过每 60 秒巡检的看门狗。只这一步，奇迹就发生了：光猫 CPU 占用从 58.4% 断崖式跌到 7.8%，外壳恢复冰凉，130 多 MB 内存当场释放；软路由上重新测速，原本死死卡住的 290 兆应声碎裂，下载速率稳定跑满 375.8 兆——局端预留的那点冗余带宽被彻底释放；晚高峰延迟抖动从 15 毫秒降到 2.1 毫秒。

第二步，更彻底：读取原机的 LOID 注册信息，把原厂光猫直接换成一台内存近 500MB、完全不带监控容器和云控地址的轻量纯桥接终端，空闲 CPU 负载只有 0.52%。

第三步，把 PPPoE 拨号、NAT 转发和防火墙规则全部收归自己完全掌控的 OpenWrt 软路由；接光猫的物理网口保持独立，配精确的主机路由，绝不桥接进局域网，从而阻断光猫自带的 IPv6 路由广播污染。

结尾

在正常的现代通信准则里，接入设备有清晰的边界：调制解调器只负责物理层信号转换；你家局域网里有哪些设备、它们何时唤醒、彼此如何通信，属于私人住宅的延伸空间。而在这两台光猫的固件里，没有任何一处物理边界被尊重——当骨干网上的审查高墙还嫌不够精细时，触角便顺着光纤，直接伸进了千家万户的弱电箱。

最黑色幽默的地方在于：这套用来监控你、分析你、随时准备劫持你流量的庞大程序，消耗的是你掏钱买的硬件内存，占用的是你按月付费的带宽，烧的是你自己交的电费。它不仅剥夺你的数字隐私，还要让你在每一次网页卡顿、每一次游戏跳 ping 时，亲身替这台粗糙而傲慢的监控机器买单。

代码不会撒谎，数据包也不会撒谎。当我们亲手拆开这个只有 256MB 的小盒子、看清那些藏在角落里的字节码时，夺回的就不只是那 85 兆被克扣的网速，更是一个现代人对自己客厅里那一小方数字边界的知情权与控制权。

（本文根据抖音创作者 nnnn 的固件逆向视频《256MB 里的老大哥：家用光猫底层监控固件》整理，文中技术细节为原视频作者的拆解发现。）
